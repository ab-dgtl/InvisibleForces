# Проект «Невидимые опоры»

Одностраничный статический сайт для заказа услуг нумерологического анализа и раскладов Таро.
Весь текстовый контент взят **дословно** из файла `Проект Невидимые опоры.docx` — ничего не добавлялось и не переписывалось. Собственные слова автора сайта ограничены только интерфейсными элементами (подписи кнопок, названия полей формы, страница политики конфиденциальности, дата в подвале).

## Цветовая гамма и стиль

- Тёмно-фиолетовая палитра (`#10062a` → `#3d2183`) + золото (`#f6ecc9` → `#a8841b`).
- Шрифты: Cormorant Garamond (заголовки), Jost (текст) — Google Fonts.
- Иконки: Font Awesome 6 (CDN jsDelivr).
- Тонкие детали: звёздное поле на canvas, медленно вращающаяся мандала за заголовком, золотые орнаменты-разделители со звездой, мягкое свечение фона, плавное появление блоков.

## Реализованные функции

1. **Hero** — название проекта, описание, плашка «Нужна только ваша дата рождения!», кнопка заказа.
2. **Зачем нужен нумерологический анализ** — 5 карточек + блок «скрытые аспекты и взаимосвязи».
3. **Тарифы** — Silver 3 500 р и Gold 15 000 р (флагманская карточка), кнопки выбора тарифа.
4. **Отзывы** — секция-заготовка (три карточки с цитатами); наполняется позже.
5. **Обо мне** — 4 абзаца + фото г. Кайлас (Тибет).
6. **Таро** — «12 сфер жизни» и «12 карт 12 месяцев», по 7500 руб, фото свечи.
7. **Темы** — 3 пункта с иконками.
8. **Форма заявки** — имя, дата рождения, телефон, почта, тариф; валидация на клиенте, запись заявки через RESTful Table API.
9. **Маска телефона** — библиотека imask (`+7 (000) 000-00-00`), валидация на полный номер (11 цифр).
10. **Согласие на обработку ПД** — обязательный чекбокс «Я даю автоматическое согласие на обработку персональных данных» + ссылка на политику.
11. **Страница «Политика конфиденциальности»** (`privacy.html`) — 11 разделов.
12. **SEO / Open Graph / Twitter Card** + микроразметка schema.org (WebSite, ProfessionalService с 4 предложениями, FAQPage).
13. **Honeypot-антиспам** — скрытое поле `website`; заполнено ботом → заявка тихо «принимается», но никуда не отправляется.
14. **Отправка заявки в Telegram** — через `js/config.js` (см. раздел ниже).
15. Адаптивная вёрстка (desktop / tablet / mobile), поддержка `prefers-reduced-motion`.

## Целевая точка конверсии

Форма в секции `#order`. Пользователь заполняет: **имя, дата рождения, телефон, почта** (+ тариф) и отправляет заявку.

## Точки входа (URI)

| Путь | Назначение | Параметры |
|------|-----------|-----------|
| `/index.html` | Главная страница (все секции) | — |

| `#about-me` | Обо мне | — |
| `#tarot` | Расклады Таро | — |
| `#topics` | Дополнительные темы | — |

| `tables/orders` | RESTful Table API | `POST` — создать заявку; `GET` — список |

## Данные

Таблица `orders` (хранение заявок):

- `id` (text) — идентификатор заявки;
- `name` (text) — имя;
- `birth_date` (text) — дата рождения;
- `phone` (text) — телефон;
- `email` (text) — почта;
- `tariff` (text) — выбранный тариф/услуга;
- `created_at` (datetime) — дата заявки.

Запись выполняется из `js/main.js` методом `POST tables/orders`. Параллельно (если включено) уходит уведомление в Telegram.

## Маска телефона

Библиотека **imask** подключается с CDN jsDelivr:

```html
<script src="https://cdn.jsdelivr.net/npm/imask@7.6.1/dist/imask.min.js" defer></script>
```

Маска: `+{7} (000) 000-00-00`. Валидация требует не менее 11 цифр. Если библиотека не загрузилась, форма продолжает работать с обычной валидацией (деградация без ошибок).

## Антиспам (honeypot)

В форме есть скрытое поле `website`, невидимое пользователю (вынесено за экран через CSS, `tabindex="-1"`, `aria-hidden`). Боты обычно заполняют все поля — при заполненном `website` форма показывает «Спасибо», но заявка не сохраняется и не отправляется.

## Политика конфиденциальности

Страница `privacy.html` содержит 11 разделов: общие положения, состав данных, цели, правовые основания и согласие, порядок обработки, хранение и защита, права пользователя, отзыв согласия, cookie, изменения, контакты.

В форме кнопка отправки сопровождается **автоматическим согласием** — обязательным чекбоксом со ссылкой на политику. Отправка без согласия блокируется.

## Отправка заявки в Telegram

### Что для этого нужно

**Вариант 1 — через сервис-посредник (рекомендуется, секреты не попадают в код сайта):**

1. Создайте бота у **@BotFather** в Telegram → получите токен вида `123456789:AA...`.
2. Узнайте свой `chat_id` — напишите боту, затем посмотрите `https://api.telegram.org/bot<ТОКЕН>/getUpdates` (или используйте бота **@userinfobot**).
3. Создайте вебхук/сценарий в **Make (Integromat), n8n, Zapier** или **Cloudflare Worker**, который принимает POST с JSON и вызывает `sendMessage`.
4. Впишите адрес этого вебхука в `js/config.js`:

```js
window.SITE_CONFIG = {
  telegram: {
    enabled: true,
    webhookUrl: 'https://ваш-вебхук-адрес',
    botToken: '',
    chatId: ''
  }
};
```

**Вариант 2 — напрямую через Bot API (без сервера, но токен виден в коде):**

```js
window.SITE_CONFIG = {
  telegram: {
    enabled: true,
    webhookUrl: '',
    botToken: '123456789:AA...',
    chatId: '123456789'
  }
};
```

⚠️ **Важно:** сайт статический, поэтому всё, что попадает в `js/config.js`, доступно любому посетителю через исходный код страницы. При варианте 2 токен бота становится публичным — используйте отдельного бота для уведомлений и не давайте ему прав сверх отправки сообщений. Если нужна настоящая защита секрета — используйте вариант 1.

Формат сообщения: имя, дата рождения, телефон, почта, тариф, дата заявки. **Заявка при этом всё равно сохраняется в таблицу** `orders` — Telegram работает как дополнительное уведомление.

## Публичные URL

- Продакшн: публикуется через **Publish tab / Hosted Deploy** (URL выдаётся платформой).
- API заявок: относительный путь `tables/orders` от корня сайта.
- После публикации замените относительные `canonical` / `og:url` / `og:image` в `index.html` и `privacy.html` на абсолютные адреса вашего домена — это нужно для корректного превью в соцсетях.

## Не реализовано / возможные доработки

1. **Отзывы** — реальные тексты и фото (блок подготовлен, нужно только наполнить).
2. **Капча** — сейчас honeypot; при активном спаме можно добавить сервис капчи (требует серверной проверки).
3. **Абсолютные URL** — заменить на боевой домен после публикации.
4. **GDPR/cookie-баннер** — при необходимости добавить баннер согласия на cookie.
5. **Фото автора** — сейчас в разделе «Обо мне» пейзаж; можно поставить портрет.
